# Ore Deal 작업 대화 기록

**기록일:** 2026-10-29  
**주제:** 4단계 턴 규칙, 장터 거래 시스템, 공개 카드 연출 및 빌드 상태

## 사용자가 확정한 규칙

- 손패는 Queue 순서를 고정한다. 새 카드는 맨 뒤에 추가하며, 광산 등록은 맨 앞 카드부터 한다. 거래 단계에서는 손패에서 제안할 카드를 선택할 수 있고, 일부 카드를 제거해도 나머지 순서는 유지한다.
- 한 플레이어의 4단계를 모두 마친 뒤에만 다음 플레이어로 넘어간다.
- 1단계에서는 맨 앞 자원 1장을 필수 등록하고, 그 이후 맨 앞 카드들을 원하는 만큼 더 등록할 수 있다.
- 2단계에서는 공개 카드 2장을 사용한다. 비활성 플레이어끼리 직접 거래할 수 없고, 활성 플레이어와만 거래·기부할 수 있다.
- 거래 카드는 손패에 들어가지 않고 거래 확정 즉시 받는 플레이어의 슬롯에 적재한다. 적재 공간이 부족하면 기존 자원을 정산한다.
- 자원 판매는 활성 플레이어의 1~3단계에서 가능하다. 정산표의 최소 수량보다 적어 0골드여도 슬롯에 2장 이상이면 판매할 수 있다. 모든 점유 슬롯이 1장씩이면 1장 슬롯도 판매할 수 있다.
- 카드 뽑기는 4단계에서만 허용한다. W 키는 새 기능에 할당하지 않는다. 4단계에는 카드 더미 위에 뽑기 안내를 표시한다.
- 장터 UI는 네 플레이어 영역과 공개 제안·비공개 손패 구역으로 나눈다. 비공개 손패는 소유자만 본다. 거래는 양쪽 모두 동의해야 확정하며, 한쪽이 취소하면 카드 이동 없이 거래 대기 상태로 돌아간다. 거래 제한 시간은 2분이다.
- 공개 카드 2장은 덱 위치에서 떠올라 옆에 놓이고 한 장씩 뒤집힌 뒤 장터 UI가 열린다.

## 이번 작업에 반영한 내용

- 서버 권한 거래 조정자 `AOreDealMarketBroker`를 추가했다. 서버가 거래 단계 감지, 공개 카드와 제안 관리, 2분 제한, 동의·취소, 거래 확정과 다음 단계 이동을 처리한다.
- 활성 플레이어는 시장 공개 카드와 자기 손패 카드를 제안할 수 있고, 상대 플레이어는 자기 손패에서 한 장 이상을 제안할 수 있다. 확정 시 양쪽 손패 카드와 사용된 시장 카드를 제거하고, 각자 받을 카드를 슬롯에 바로 적재한다.
- 거래 확정 전 양쪽 슬롯의 적재 가능 여부를 검사한다. 빈 슬롯이 없을 때는 정산 가능한 슬롯 중 예상 보상이 가장 낮은 슬롯을 우선 정산하고, 동률이면 적은 카드 수의 슬롯을 먼저 고른다. 다른 슬롯에 2장 이상이 있으면 1장 슬롯은 정산 후보에서 제외한다. 이 우선순위는 현재 코드의 결정이며 README에도 기록했다.
- 장터 UI에 네 플레이어 구역, 공개 제안, 소유자 전용 손패, 제안 카드 선택·회수, 양쪽 동의 및 취소 버튼을 구성했다. 비공개 손패의 카드 종류는 다른 플레이어에게 복제하지 않고 손패 장수만 공개한다.
- 공개 카드 연출은 각 클라이언트에서 실제 카드 덱의 화면 좌표를 시작점으로 사용한다. 두 카드는 나란한 위치로 이동한 뒤 차례로 앞면이 보이며, 1초 연출 뒤 거래 UI가 열린다. 이 연출은 화면 UI이며 월드의 카드 메시 애니메이션은 아니다.
- 기존 강제 정산과 판매 경로에 판매 알림을 연결했고, `README.md`에 합의한 규칙과 현재 구현 메모를 추가했다.

## 빌드 및 작업 상태

- Unreal Engine 5.8 `TeamProjectEditor Win64 Development` 빌드가 성공했고, 최종 C++ 모듈 DLL 링크까지 완료했다.
- 빌드 오류로 발견한 UMG 버튼 람다 바인딩과 `FVector2D` 상수 사용 문제를 수정한 뒤 성공 빌드를 확인했다.
- 빌드 중 DLL이 잠겨 있어 저장 상태를 확인하고 에디터를 닫은 뒤 컴파일했다. 완료 후 `TeamProject` 프로젝트를 에디터에서 다시 열었다.
- 프로젝트에는 C++ 변경이 반영됐지만, 2~4인 실제 네트워크 플레이를 통한 거래·취소·제한 시간·강제 적재 실기 검증은 아직 하지 않았다. 블루프린트의 3단계 적재 흐름과 월드 메시 연출도 별도로 확인해야 한다.

## 다음 작업에서 이어서 확인할 항목

1. 2~4인 네트워크 세션에서 각 플레이어의 손패 비공개 유지, 활성·비활성 제안, 양쪽 동의, 취소 후 재협상, 2분 초과 처리를 확인한다.
2. 거래 후 받은 카드가 양쪽의 올바른 슬롯에 즉시 들어가고, 슬롯 부족 시 정산 우선순위 및 골드·버린 카드 더미가 갱신되는지 확인한다.
3. 남은 공개 카드가 3단계에서 활성 플레이어 마차에 적재되고, 4단계 카드 3장 보충 후 다음 플레이어로 넘어가는지 확인한다.
4. 에디터의 월드 카드 덱·카드랙·상인 배치와 Blueprint 시각 갱신이 새 C++ 흐름과 맞는지 확인한다.
